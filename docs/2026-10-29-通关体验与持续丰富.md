# 通关体验与持续丰富

## 本轮验收范围

- 十二道制书均可保存 PNG；保留姓名、官阶、正文与书法字体，手机按钮可触达。
- 凯旋首页有庆典画面、音乐和音效；静音、关闭弹窗和后台切换正确停止声音。
- 所得展示覆盖封赏、军饷、装备、称号、委托谢礼、奇遇和藏品，区分已获得与待完成。
- 章节挑战、委托和收藏能从结算直接抵达对应页面；全部页面保持单屏翻页。
- 验证后同步 GitHub 并发布正式站，核对固定网址资源。

## 2026-10-29 实测发现

完整测试档案在 320×568、390×844、1280×720 没有纵向溢出，装备出现在清单中。但手机 45 页、桌面 37 页说明信息架构仍需改造。应改为按类别直达，藏品使用图文分页；不能以布局测试通过替代可用性验收。

## 持续丰富的顺序

1. **先让已有内容可见**：凯旋分类目录、委托状态和可领奖提示、藏品来源和套组进度，展示真实奖励图与当前装备。
2. **让重玩改变体验**：每回保留原版，增加明确标注的精进挑战；逐项加入风向变化、移动目标和机关组合，挑战说明在开局可见，失败能立即重试。
3. **让收集影响选择**：把现有套组称号、随身佩物、重复藏品兑换和装备能力解释清楚；先解决奖励用途，再增加藏品数量。
4. **让 NPC 带来故事**：委托链按前置任务解锁，完成时明确展示人物回应、谢礼和下一件事；补充已完成故事的回顾。
5. **持续关卡扩展**：每批新关先验证一个新操作变化，再组合已有机关；避免只缩小命中区或加快力道条。新关必须包含目标说明、失手反馈、独特奖励、重玩目标和手机实测。

以上扩展顺序属于设计方案；只有经实际实现与验证的项目才能标记完成。


## 本轮实现与核对（2026-10-29）

- 每章结算、最终制书、档案中的历史封赏均有保存图片入口。导出2400×1350 PNG，右起竖书，真实姓名及文书文字逐字绘制，本地书法与生僻字补充字体烧入图片。
- 凯旋使用朱金庆典背景、飘带、专用108 BPM配乐与入场音效；弹窗内可启停声音，遵循浏览器手势策略。
- 六个分类入口：凯旋、制书、军功所得、所得藏品、待完成、再启一程。只出现有内容的分类，已完成的缺项不再占一张空页。
- 所得包含十二阶封赏、军饷收入与结余、已领委托的物品和称号、奇遇纪念、装备阶数与效果、佩物、衣装、解锁箭具、全部已得藏品数量。藏品按七套图卡呈现。
- 320×568、390×844、1280×720分别遍历部分收集和全部收集的战报，核对每件物品与装备均可见；单屏分页不依赖上下滚动。
- 技术证据：`tools/decree-export-check.mjs`、`tools/finale-delivery-check.mjs`、`tools/honors-shot-check.mjs`、`tools/audio-check.mjs`。截图与下载是技术检查，不等于用户审美或实体手机验收。

## 关卡扩展的约束

先做3关小包实测，再扩到一章。每关在表中写清：练习目标、机关组合、预告方式、失手原因、三星条件、独有纪念、预计时长。装备带来不同手感与取舍，不能把买装备变成通过关卡的硬门槛。训练场保持无惩罚，正式挑战和训练记录分开。新增难度应来自选择与时机，不只靠缩小金区。

## 观察哪些真实反馈

记录匿名聚合的开局、首箭、首次通章、首次领奖、首次补星、主动再练等事件；现有统计能说明访问量，不能自动证明游戏好玩。先看玩家在哪一关反复失手、哪里找不到入口，再决定增加关卡还是改交互。暂不加入付费随机奖励、断签惩罚或强制每日任务。
